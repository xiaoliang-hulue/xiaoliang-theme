# 小亮主题视觉与动效升级设计

- 日期：2026-09-30
- 状态：已由用户确认
- 目标版本：1.5.0
- 兼容级别：向后兼容，不删除或重命名现有 Token 与 class

## 1. 背景与目标

小亮主题已经具备浅色/深色 Token、26 个组件、页面模板、无障碍审计和完整构建链路。当前主要问题是整体偏冷静、蓝灰色占比高，组件状态变化较快且缺少统一的运动语言。

本次升级的目标是：

1. 在不破坏现有 API 的前提下，提升视觉舒适度、配色协调度和层次感。
2. 建立统一、清晰有节奏的动效系统，并默认覆盖核心组件。
3. 让公开开源使用者能够理解、复制和按需关闭动效。
4. 通过自动化审计和在线预览，保证长期维护质量。

## 2. 非目标

- 不重写组件类名、Token 名、构建脚本或公开 API。
- 不引入前端框架、运行时状态库或外部 CDN。
- 不以持续闪烁、无限大幅移动、霓虹光效或大面积紫色渐变作为默认视觉。
- 不把预览站改造成营销官网；它仍以组件和页面模板参考为首要用途。
- 不在本次自动注册 GitHub 账号或代替用户接受平台协议。

## 3. 已确认设计方向

### 3.1 动效气质

采用用户选择的 **B：清晰有节奏**。

- 交互反馈明确、快速，状态迁移连贯。
- 以 160 至 320ms 为主要时长，页面入场可使用更长节奏。
- 使用自然减速和轻微回弹，不使用持续晃动和夸张旋转。
- 动画服务于层级、方向、因果和状态变化，不单纯为了装饰。

### 3.2 配色方向

采用用户选择的 **B：海蓝 × 青绿 × 暖金**。

- 海蓝继续承担品牌、主按钮、导航和关键操作。
- 青绿用于成功、数据增长和辅助操作。
- 暖金仅用于收藏、提醒和有限的关键强调。
- 中性背景加入轻微暖度，减少大面积蓝灰带来的单调感。
- 深色模式保持柔和蓝黑底，不把浅色模式简单反相。

### 3.3 发布定位

仓库以公开开源、可复用为目标：

- 保留 MIT 许可。
- README、迁移文档、更新日志和 GitHub 操作指南面向首次使用者。
- 通过 GitHub Pages 提供在线预览。

## 4. 系统架构

### 4.1 Token 单一真值

`css.json` 继续作为颜色与基础 Token 的唯一真值。所有 Token 变更通过 `npm run build:tokens` 生成到 `colors_and_type.css` 的浅色、显式深色和系统偏好深色作用域。

### 4.2 兼容策略

- 现有颜色、排版、间距、圆角、阴影、断点和语义 Token 全部保留。
- 现有组件 class 与交互属性全部保留。
- 只新增 Token、工具类和状态增强。
- 旧项目替换 CSS/JS 后无需改动业务代码。
- 默认视觉会发生变化，因此更新日志和迁移文档必须明确说明。

### 4.3 动效层

新增统一动效 Token，至少覆盖：

- 时长：快速反馈、常规交互、强调过渡、页面入场。
- 缓动：标准、强调、轻微回弹。
- 距离：小位移、中位移、大位移。
- 缩放：按压缩放、悬浮缩放。
- 错峰：列表和卡片入场延迟。

组件只消费统一 Token，不在每个组件中重复定义零散时长与缓动。

### 4.4 动效控制

- 默认启用完整动效。
- `data-motion="off"` 关闭非必要动效。
- `data-motion="subtle"` 使用更短、更小的动效。
- 系统 `prefers-reduced-motion: reduce` 优先级最高，应接近完全关闭动画和过渡。

## 5. 组件改造范围

### 5.1 反馈与表单

- Button：悬浮抬升、按下压缩、加载扫光，保持键盘焦点清晰。
- Input、Textarea、Select：焦点光圈、错误与成功状态过渡，不依赖颜色单独传达状态。
- Checkbox、Radio、Switch：勾选、滑块与轨道状态连续变化。
- Progress：进度值渐进变化，不确定进度继续支持减少动效降级。

### 5.2 内容与数据

- Card：悬浮时轻微抬升，边缘层次与阴影同步变化。
- Table：行悬浮、排序和加载状态动效。
- 列表、指标卡和仪表盘：首次进入使用短距离错峰渐入。
- 收藏、提醒、数据增长使用暖金和青绿语义色进行有限强调。

### 5.3 导航与结构

- TopNav、SideNav：激活背景或指示条平滑迁移。
- Tabs：标签切换具有方向感，ARIA、键盘操作保持不变。
- Accordion：内容展开和收起连续变化，原生语义保持不变。
- Breadcrumb、Pagination、Stepper：状态变化使用统一反馈节奏。

### 5.4 浮层与反馈

- Dropdown、Tooltip、Modal、Drawer、Toast 补齐进入和退出状态。
- 关闭动作先完成退出动画，再设置 `hidden`，避免瞬间消失。
- ESC、遮罩关闭、焦点陷阱、多层叠加、滚动锁和 `aria-hidden` 行为保持正确。
- 减少动效模式应立即关闭，不等待动画结束。

## 8. 验证策略

发布前必须通过：

1. `npm run build`。
2. `npm run audit`，包括颜色对比度、ARIA 和图标一致性。
3. 浅色、深色和系统跟随三种模式。
4. 桌面与手机视口。
5. 完整动效、`subtle`、`off` 和系统减少动效四种控制模式。
6. 键盘焦点顺序、ESC、遮罩关闭、Tabs 方向键和浮层焦点陷阱。
7. Modal、Drawer、Toast、Dropdown、Tabs、Accordion 等交互回归。
8. 旧版页面在只替换 CSS/JS 后仍能正常运行。

## 9. 风险与控制

- **视觉变化过大**：提供 `subtle` 和 `off` 控制，迁移文档给出明确示例。
- **动效影响可访问性**：系统减少动效优先，焦点和语义不依赖动画。
- **颜色对比度回退**：所有新颜色进入现有对比度门禁，失败时阻止发布。
- **预览性能下降**：动效优先使用 `transform` 和 `opacity`，避免大量布局动画。
- **首次 GitHub 操作受阻**：在认证和平台确认节点暂停，提供逐步指导。

## 10. 验收标准

- 现有 Token 与 class 无删除、无重命名。
- 所有核心组件具备统一且可关闭的动效。
- 海蓝、青绿、暖金在浅色和深色模式下层次协调。
- 全部自动化审计通过。
- 预览页在桌面和手机下无重叠、溢出或不可读文本。
- 文档能让未使用过 GitHub 的维护者完成仓库创建、推送和 Pages 发布。
- 最终代码推送到用户指定的 GitHub 仓库。
